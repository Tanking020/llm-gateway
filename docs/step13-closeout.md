## 五、能讲给面试官的三件事（每件都有取舍 + 证据）

### ① 反代层的两个「默认值陷阱」

- **`proxy_buffering` 默认 `on`** → SSE 被攒成一次性到达（📎 受控实验：**2.07 s 全到齐** vs 关掉后 **0.07/0.47/0.87…** 逐帧）
- **nginx 默认只解析上游一次** → app 重建换 IP 后**永久 502**（📎 日志里 `upstream: "http://172.18.0.2:8000"` 就是旧 IP）→ 加 `resolver + resolve` 后同一场景 **200**
- 收获：**「配好了」不等于「验证过」** —— 两个都是默认值，都不报错，都是静默坏

### ② 测试里的「哨兵」：报错而不是静默替换

- 问题：如果 `conftest` 悄悄把真上游换成 Fake，「这个用例其实没测上游」就被彻底掩盖
- 做法：换掉**工厂**（不是 override 依赖，因为 `dependency_overrides.clear()` 会清掉），返回一个**装了会炸 transport** 的客户端 —— 只在真发请求那一刻抛 `RealUpstreamForbidden`
- 收获：**守卫的价值在于「让错误无法被忽略」，不在于「让错误不发生」**

### ③ 两个类型检查器的分叉：`mypy` 绿 ≠ 编辑器绿

- 📎 同一段 `getattr(pool, "checkedout", None)` + `int(method())` → **mypy 0 issues / pyright 2 errors**
- 根因：mypy 把 `getattr` 的返回值当 `Any`（逃逸口），从此整条链放行
- 决定：质量门 4 道 → **5 道**，规则是「**并集**」（两套都过才算过）
- 收获：**「当前有几处错」不能作为「要不要加守卫」的依据** —— 要看那一类错会不会再发生、现有守卫为什么没抓到
